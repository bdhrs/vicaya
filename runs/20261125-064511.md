## Retrospective
- [POSITIVE] Evidence: a script that extracted every Section-1 sutta ref from all 47 notes and ran sc_parallels gave a complete, mechanical candidate list in one pass. Cause: series notes share a heading shape. Fix: preserve as the method for corpus-wide audits. Scope: global.
- [POSITIVE] Evidence: reading CBETA XML directly by line marker (a 20-line reader) overturned three of four claims in the 2026-08-24 note (SĀ 560 has the restlessness mode; MĀ 210 has the ekaggatā gloss; MĀ 97 keeps upādāna as 受) and found MĀ 55 for SN 12.23, which SuttaCentral's table omits. Cause: search-chinese snippets are too short to judge content. Fix: a helper to read N chars from a Taishō line marker. Scope: global.
- [WORKFLOW] Evidence: the Haiku 3b agent picked Chinese query terms that mostly hit the wrong senses (家家 as "house to house", 七想 as 七勤法), so each lead had to be re-read by the orchestrator. Cause: term choice needs the parallel's own wording. Fix: give 3b agents terms taken from sc-parallels text_lzh, not invented ones. Scope: local.
- [CONFUSION] Evidence: the first draft marked SN 43.2 "cleared by SĀ 890" and AN 2.31 "cleared by SĀ 710" on snippet-level matches; the source-armed reviewer caught both (SĀ 890 has only the eightfold path, which itself became a new tier-B finding). Cause: treating a matching term as a matching idea. Fix: read the whole Chinese sūtra before marking "cleared". Scope: global.
- [BEHAVIOR] Evidence: nothing.
- [BUG] Evidence: in the Bash tool on macOS (zsh), an unquoted `$SL` holding "--slug X" was passed as one argument and the helpers rejected it. Cause: zsh does not word-split. Fix: document alongside the existing shell-loop pitfall. Scope: global.
- [DOC] Evidence: the sc-parallels table both missed real parallels (MĀ 55 for SN 12.23) and listed weak ones (T 150A for AN 3.76). Cause: archive metadata. Fix: SKILL note that SC table absence/presence must be content-checked in CBETA both ways. Scope: global.
