## Retrospective
- [POSITIVE] Evidence: the source-armed reviewer found a fabricated Pāḷi blockquote (the Mahāniddesa `maññanā thambhanā mānena cetasā`, spliced from the Vibhaṅga) and a user-supplied compound that overturned the note's whole thesis (Theragāthā apadāna 3 pairs the dehorned bull with *nikkhittamāna-dappa*). Cause: a Phase 2 sub-agent reported a large negative, the orchestrator checked it, and the check was right. Fix: none — this is the harness working as designed. Scope: local.
- [WORKFLOW] Evidence: the user's "bull with horns removed" turned out to be *usabhachinnavisāṇasama*, and my own sweep had reported it absent because I searched *sīṅga* for "horn" when the Pāḷi in that compound is *visāṇa*. Cause: I delegated a simile sweep to a sub-agent with a list of candidate words and did not seed the family sweep with the philological fact that horn-words vary within one passage. Fix: preserve — when a user supplies a term mid-run, it is a lead, and log the compound family as a new search seed before continuing. Scope: global.
- [CONFUSION] Evidence: three separate false-zero cascades. The CST canon DB returns 0 for *paccabhāmi* across all 217 tables. The *Theragāthā* "the tenth simile" was a CST paragraph number leaking into prose. AN 3.80 was assumed to be *Sumanakavatthu* and is actually *Cūḷanikāsutta*. Cause: paragraph numbers, sutta numbers and a paragraph index were treated as interchangeable, and an abridged corpus was trusted as complete. Fix: the abridgement is now in the skill's shared preamble as a known corpus limitation. Scope: global.
- [BEHAVIOR] Evidence: a Phase 2 sub-agent ran `rm -f temp/*.json temp/s*.txt` in the shared repo-local temp directory, wider than its own files. Cause: no rule scopes temp cleanup to a run directory. Fix: preserve — the Phase 7 sweep is orchestrator-only and run-scoped; consider stating that sub-agents must not delete anything outside `temp/<slug>/`. Scope: local.
- [BUG] Evidence: `search-chinese --text` ids are not Taishō numbers, and a wrong id silently returns an unrelated text with no error — `--text T0452` returned a Maitreya sūtra and produced a false zero on MA 24, which is under T0026. ## Improvement suggestions
- Suggest: add the CST canon DB's abridgement to the shared preamble as a corpus limitation — `paccabhāmi` and `pabbatavāsara` return 0 across all 217 tables and AN 3's Brāhmaṇavagga holds 10 suttas where the full edition has ~33, so 0-hits there cannot establish absence. Note that the SuttaCentral root Pāḷi archive is the better oracle but is ALSO partial (the Ālavikūṭasutta is absent from its MN folder), so the two-source absence rule is not fully satisfiable on this machine.
- Suggest: add a warning to `search-chinese` that `--text` ids are not Taishō numbers and that a wrong id returns a real text with no error rather than failing — this silently produced a false zero on MA 24, and a false zero in CBETA is more dangerous than a false positive.
- Suggest: record in the SKILL that `resolve-citation` on the abridged CST edition can resolve a *paranum* to a sutta title that does not match the well-known numbering for that reference (AN 3.80 → Cūḷanikāsutta), and that a well-known sutta identity should be confirmed against the SuttaCentral root Pāḷi before being relied on.
- Suggest: the 4b agent could not gate because the Phase 4 gate was missing while the 4a agent was still writing, and it retried 14 times over 9 minutes. The parallel-dispatch section should say that a gated-later-phase agent should log its work and stop rather than poll, since the orchestrator backfills gates in ascending order.
- Suggest: record the Horn-words finding as a general search rule: within one passage the same idea takes different words (*visāṇa* / *siṅga* for horn; *nivāta* / *nivāreti* are different DPD formations, ni+√vā+ta vs ni+vāre+ti), so a single-stem sweep misses half a family and a cognate assumption can be silently wrong.
- Suggest: /vicaya-pre should treat "a user supplies the search term during the run" as a first-class event — the term's own compound family should be re-swept and any earlier negative re-opened before synthesis proceeds.
