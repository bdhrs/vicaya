## Retrospective
- [POSITIVE] Evidence: the commentarial fourfold (āgamanīya-, adhigama-, okappana-, pasāda-saddhā) was established directly from the aṭṭhakathā/ṭīkā tables with Pāḷi and English side by side, incl. the intra-commentarial divergence (DN-a "sā duvidhāpi idhādhippetā" vs MN-a/AN-a okappana-only). Cause: the canon DB carries these texts with paranum addressing. Fix: preserve — for commentarial doctrine, pull the aṭṭhakathā/ṭīkā text itself before any secondary summary. Scope: global.
- [WORKFLOW] Evidence: validate_note.py returned PASS on a note whose frontmatter held four canon_refs entries that YAML parsed as mappings, not strings (Rule F1 colon-space in `near: `). Cause: the validator does not strictly type-check the ref lists. Fix: see improvement suggestions. Scope: global.
- [CONFUSION] Evidence: the cross-check caught a flattened "commentarial consensus" that hid a real divergence between DN-a and MN-a/AN-a. Cause: synthesising three commentaries as one voice. Fix: treat every commentary as a separate witness by default. Scope: global.
- [BEHAVIOR] Evidence: nothing — gate, citation-shape, coverage, self-audit and index checks were all run in order; the only stop was the sync remote failure below.
- [BUG] Evidence: sync_notes.py committed the note locally but `git pull --rebase` failed with "Repository not found" over the SSH remote git@github.com:bdhrs/vicaya-notes.git, though gh auth (https token) is valid and the repo exists. Cause: SSH key/agent not authorized for the private repo, or remote protocol mismatch. Fix: sync script should detect an unreachable remote and print the URL + protocol. Scope: global.
- [DOC] Evidence: SKILL states the vault is "its own git repo"; in practice $VICAYA_VAULT_PATH (/home/bodhirasa/MyFiles/Obsidian) is not a repo — only its Vicaya/ subfolder is. Cause: ambiguous wording. Fix: name the subfolder explicitly. Scope: global.
