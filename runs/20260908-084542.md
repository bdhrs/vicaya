## Improvement suggestions
- Suggest: replace the per-agent "read the shared preamble from SKILL.md" step in Sub-agent dispatch with a pre-extracted preamble file (e.g. `skill/vicaya/PREAMBLE.md`) that agents read instead — the ~40k-token full-file read multiplied across a parallel wave is what made one real run consume roughly half a user's quota before any searching, and the user halted the run over it.
- Suggest: add a rate-limit warning to the Parallel dispatch paragraph stating the fixed per-agent preamble cost and recommending inline gather for thematic runs; the section currently presents parallel dispatch as free wall-clock savings with no cost note.
- Suggest: amend Hard Rule 9 and Rule F2 to warn that for RANGE-STORED books (Dhammapada, and the others whose resolver output carries a range label such as "DHP1-20") the `human` field's chapter/vagga name is the range table's FIRST section, not the cited verse's own section — so copying it verbatim into a citation asserts a false vagga. Recommend deriving the vagga from the book's `rend='chapter'` headings and give the one-line SQL for it.
- Suggest: document in "Calling the helpers" that `--quiet` is accepted only by the search/fetch/lookup helpers and NOT by the `scratch-*` subcommands, which exit with an argparse error; the current wording implies a uniform call template is always safe.
- Suggest: document the `scratch-check-coverage` response shape (`library_hits_gathered`, `unaccounted`) in the Library coverage check section — a wrong key guess returns an empty list rather than an error, so it can read as a clean result.
- Suggest: add to the Phase 7 index-update step that inserts into `summary-vicaya.md` and `catalog-by-topics.md` must be anchored on the target section HEADING (matching its exact bytes — `## Pāli Bhāsā` uses `Pāli`, not `Pāḷi`) and never on a body line, and that the agent should verify with a grep that its new line appears exactly once and in the right section. Both index files already carry damage consistent with earlier runs violating this.
- Suggest: add a repair task to TODO for the two pre-existing index defects noted above (the 33-fold duplicated bullet and the stray "the " prefix in `catalog-by-topics.md`; the linkless table row in `summary-vicaya.md`), since a research run should not be silently mass-editing shared index files.
