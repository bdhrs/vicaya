## Retrospective
- [POSITIVE] Evidence: Locating the local `dpd-db/resources/other-dictionaries` corpus (Cone, CPD, CPED, PEU, MW, Apte, Nyanatiloka, DPR as raw JSON/SQLite/CSV, not just build tooling) and writing one unified `lookup.py` script against all of them in one go paid off enormously — every subsequent word lookup was one command instead of nine separate ad-hoc format investigations. Cause: the "other-dictionaries" repo ships exporters, not obviously a queryable API, but the raw `source/` files underneath are directly loadable. Fix: keep this pattern — for any future lexicographic task, check for raw source files under exporter/build tooling before assuming a dictionary is unqueryable. Scope: global.
- [POSITIVE] Evidence: Finding Ānandajoti Bhikkhu's brand-new (2026) *Dhammanīti: Dhamma Wisdom* translation in the library folders index (via a plain `search-library-folders "Dhammaniti"` call) turned out to be the actual primary source the user's CSV annotations were drawn from — the footnote style matched exactly. This let nearly every word be verified in its real verse context rather than from dictionary citations alone. Cause: the library folders index covers newly-added ebooks, not just old scans. Fix: always run a library-folders search for the primary text *before* assuming only the canon DB or EBC vault can supply source-text context — non-canonical/paracanonical texts (nīti literature, commentaries, modern translations) often live there instead. Scope: global.

- [WORKFLOW] Evidence: Given the 65-word scale, per-word research was done by the orchestrating session directly rather than via the standard per-phase sub-agent dispatch (Agent tool calls in this environment resolved synchronously as "you are now the fork" rather than truly backgrounding), so all 5 batches of ~13 words were processed serially in one long session. This worked but consumed a very large amount of context/turns. Cause: unclear whether the harness's Agent/fork tool genuinely backgrounds in this environment, or whether the single dispatched fork call actually just becomes the current turn's continuation. Fix: for a future task of this scale, either confirm fork backgrounding behavior before committing to a plan that assumes it, or deliberately plan for serial in-session batch processing from the start rather than assuming parallel dispatch will work. Scope: global.
- [BEHAVIOR] Evidence: The most significant single finding — that DPD's `vibudha` headword is glossed "with distorted wisdom" when both MW's Sanskrit cognate and the actual Dhammanīti verse context establish the opposite, positive "very wise" sense — was caught only because the primary-source verse happened to be checked directly rather than trusting DPD's own gloss. This is exactly the kind of error a purely dictionary-cross-reference approach (without primary-text verification) would have missed or even reinforced. Fix: for any DPD-feedback-style task, always check the word's actual attested usage in a primary text before trusting an existing DPD gloss at face value, even when DPD isn't flagged as obviously wrong. Scope: global.
- [DOC] Evidence: Several CSV citations (5 of them) named a verse number that did not match where the word actually appears in Ānandajoti Bhikkhu's 2026 translation, but the word was always genuinely present elsewhere nearby — consistent with the compiler having used the underlying Bechert/Braun PNTB critical edition's own verse numbering rather than the new translation's renumbering. This pattern was only noticed because each word's context was independently searched rather than trusting the cited verse number blindly. Fix: no SKILL change needed — this is exactly what Hard Rule 9 (paragraph numbers are book-global, verify with resolve-citation) already teaches, just applied to a non-CST source (a translated ebook) instead of the canon DB. Worth generalizing Hard Rule 9's spirit ("never trust a cited locator without independently confirming it") to any external primary source, not just CST book codes. Scope: global.
