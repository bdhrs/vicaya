## Retrospective
- [POSITIVE] Evidence: the two reviewers caught five real defects the drafting pass missed (Abhidhamma mis-tiered as T2, Ud 6.3 vs 7.3, Sn 1.5 vs 2.5, the T99 answer-verse misquotation, and the SN35.228 flood/ocean conflation). Cause: the source-armed reviewer had canon-helper access and resolved each blockquote rather than reasoning about it; the external GLM review independently found the tier and taṇhā gaps. Fix: preserve the two-reviewer pattern (external chain + source-armed read-only subagent) for any note with more than ~20 blockquotes. Scope: global.
- [WORKFLOW] Evidence: the note ran ~400 minutes and produced an 8,000-word note against a 3,500-word guide. Cause: a four-part question scoped to "all strata, all traditions" has no natural stop condition, and each new stratum (Abhidhamma, Sarvāstivāda, Yogācāra, Vedic) legitimately added sources. Fix: for explicitly cross-canon questions, set the Target line as a *stratum count* (e.g. "one locus per stratum, no more") so the stop condition is structural rather than volume-based. Scope: global.
- [CONFUSION] Evidence: `resolve-citation s0305m_mul 172` returns "SN45.172 Oghasutta" while the same row's `sc_code` in dpd.db sutta_info is SN45.171; the reviewer independently confirmed via SuttaCentral msdiv that SN45.171 is correct. Cause: the CST Burmese Esanāvagga carries an extra sutta (Tasināsutta) that Sinhalese mss lack, shifting the whole Oghavagga by one; `resolve-citation` renders the CST paranum as the SC sutta number. Fix: see improvement suggestions. Scope: local to the helper.
- [BEHAVIOR] Evidence: the first Vinaya-absence claim was written from a compound SQL filter without printing the excluded rows, and the audit trail named the wrong false positives (goghāta rather than goghaṃsikā) and checked only two of five tables. The conclusion was right; the evidence trail was not. Cause: trusting a zero count without inspecting what was excluded. Fix: when logging an absence, print the excluded hits and name each false-positive form. Scope: global.
- [BUG] Evidence: Phase 4c (WisdomLib) failed on every one of nine terms with HTTP 403 behind a Cloudflare JS challenge, and the r.jina.ai text proxy also failed the CAPTCHA; the skill still documents WisdomLib as a plain fetch. Cause: the site added bot protection since the skill section was written. Fix: see improvement suggestions. Scope: global.
- [DOC] Evidence: two reviewer claims about Suttanipāta numbering contradicted each other (one said Sūciloma = Sn 2.5, the other Sn 1.5); only the canon DB settled it (SNP2.5). Cause: Sn numbering differs between the DPD codes, PTS, and SuttaCentral; the skill does not warn about this the way it does for AN nipātas. Fix: extend Hard Rule 12's book-code warning to numbered verse texts. Scope: global.

## Improvement suggestions
- Suggest: `resolve-citation` should prefer the `sc_code` column over the CST `paranum` when building the `human` string — the SN45 Oghavagga is off by one because CST's Burmese Esanāvagga carries an extra Tasināsutta, and any agent following Hard Rule 9/F2 verbatim would "correct" a correct citation into a wrong one.
- Suggest: document in Hard Rule 12/9 that Suttanipāta sub-numbering in the canon DB (SNP2.5 = Sūciloma, SNP9 = Hemavata, SNP10 = Āḷavaka) differs from older PTS order, and that `resolve-citation`'s `human` for Sn/Ud uses DPD codes (SNP17, UD63) that must be translated before citation — two real numbering traps hit this run.
- Suggest: record that WisdomLib is now Cloudflare-gated for scripted fetches (9/9 terms returned 403 this run) and name a fallback — the library index holds the *Encyclopedia of Indian Religions* (Buddhism) volume, which covers ogha and āsava and is a better Phase 4c substitute than an unreachable web page.
- Suggest: add an explicit guidance line for questions scoped to "all strata / all traditions": name a per-stratum source ceiling in the Target line so the run has a structural stop condition instead of drifting to maximum breadth in every stratum.
- Suggest: add a note to the Phase 2 absence procedure that the `ogh` stem's canonical false positives are moghapurisa/moghapurisā, moghasutta, and the Kaṭhina term goghaṃsikā, and that raw `LIKE '%ogha%'` counts in the Vinaya are ~100% noise.
