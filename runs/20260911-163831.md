## Retrospective
- [POSITIVE] Evidence: the `search-sanskrit` helper on GRETIL settled the central etymological question in one step — `kaukṛtya`/`kukṛtya` appear in 144/12 Buddhist Sanskrit files and in ZERO Vedic, Epic, Purāṇic or Jain files, with one non-Buddhist literary use (Pañcatantra) meaning a concrete "bad deed". Cause: `VICAYA_GRETIL_PATH` is now configured, and the whole-tree grep is fast enough to give a distribution rather than a hit list. Fix: none — this is the model for future diachronic runs. Scope: global.
- [POSITIVE] Evidence: the Commentary Evidence section found, in the ṭīkā layer, explicit statements that kukkucca shares uddhacca's `avūpasama` characteristic (`s0401t_tik` §14, `abh02t_tik` §367) — i.e. the tradition answers the user's question in its own words. Cause: searching the ṭīkā tables (`*_tik`) and not stopping at the aṭṭhakathā. Fix: prescribe a ṭīkā pass for any term-meaning question. Scope: global.
- [POSITIVE] Evidence: the source-armed second reviewer caught seven citation-paranum errors (rowids cited as paragraphs) that every other check had passed — `abh01a_att` §1908/1909/1910, `vin07t_nrf` §1234, `s0505a_att` §931/§978, `s0515a_att` §84, `abh02a_att` §556. Cause: the resolver's "nearest preceding non-empty paranum" names the paragraph a row falls inside, and a continuation row whose text begins "932." still resolves to 931. Fix: keep dispatching the source-armed reviewer; it earns its cost. Scope: global.
- [WORKFLOW] Evidence: I cited ~40 canonical and commentarial paragraphs and had to re-resolve every one after the reviewer's findings, because the "owning paragraph" heuristic fails on rows that carry their own `<hi rend="paranum">N</hi>` but a blank `paranum` column. Cause: no documented helper for "which paragraph does this quoted string belong to". Fix: Suggest a `find-passage <table> <text-fragment>` subcommand that returns the row's own inline paragraph number when present, else the nearest preceding non-empty one, with a `method` field saying which was used. Scope: global.
- [CONFUSION] Evidence: I initially wrote "the digital dictionary splits kukkucca into three senses" when `dpd_headwords` has four (`kukkucca 4 | remorse; regret; repentance`). Cause: my first query printed only rows matching `LIKE 'kukkucca%'` in the order the DB returned them and I read three; I did not count. Fix: Suggest that term-meaning runs always state the headword count from `SELECT count(*)`. Scope: global.
- [BEHAVIOR] Evidence: the first cross-check integration round was written as a Python script whose single-quoted strings contained an unescaped apostrophe ("Vism's"), the script died with a SyntaxError, and one of the 23 intended fixes (the AN 5.193 / SN 46.55 `vūpasanta` correction) silently did not land — the verification pass caught it as "NOT LANDED". Cause: batching many edits into one ad-hoc script without re-checking the item count after the failure. Fix: Suggest that after any batched edit script, the agent re-lists the intended change-set and confirms each against the file, rather than trusting the "failures: 1" line. Scope: global.
- [BUG] Evidence: `scratch-check-coverage` reported 91 unaccounted library documents after I had already written a "reviewed as a set" rejection row, because the row listed ids as "#765, #860" rather than "Calibre #765, Calibre #860" and the matcher needs the literal prefix. Cause: the check's documented match forms are `calibre-<id>` and `Calibre #<id>`; a bare `#<id>` does not match. Fix: Suggest that the coverage check's output or docs state the exact required token form inline, or accept `#\d+` too. Scope: global (docs).
- [DOC] Evidence: this run was an enrichment of an existing note, and the skill's instruction is "keep its filename and date" while also "update the footer" — leaving the question of which date the footer carries. I put the original date in frontmatter and both dates in the footer. Cause: the rule does not say. Fix: Suggest one sentence in Phase 7 stating the convention for enrichment runs' footer line. Scope: global.

## Improvement suggestions
- Suggest: add a `find-passage <table> <fragment>` helper (or extend `resolve-citation` with a `--contains` flag) that resolves a quoted Pāḷi fragment to its paragraph using the inline `<hi rend="paranum">N</hi>` when present, falling back to the nearest preceding non-empty `paranum`, and reporting which method it used. Rationale: a continuation row whose text begins "932." still resolves to 931 under the current heuristic; this caused seven citation errors in one note, all of which passed validate_note and check-citation-shape.
- Suggest: document in Phase 2 that for term-meaning questions the search must include the `*_tik` sub-commentary tables and the `s0515m/s0516m` (Niddesa) pair, not just sutta mūla and aṭṭhakathā. Rationale: the single most load-bearing sentence in this run (the ṭīkā's unification of uddhacca-kukkucca under `avūpasama`) lives only in the ṭīkā layer.
- Suggest: when `scratch-check-coverage` reports a large residual tail, have the tool emit a ready-to-paste rejection row containing the ids already in the `Calibre #<id>` form the matcher accepts. Rationale: 91 → 0 took two manual rewrites purely because of token format.
- Suggest: in the `channel tuning` step, note that an unknown channel defaults to probationary; promotions should record the channel name exactly as `search-youtube` returns it. Rationale: Ajahn Punnadhammo's channel was absent from the allowlist entirely, so the same talk was probationary in two consecutive runs.
