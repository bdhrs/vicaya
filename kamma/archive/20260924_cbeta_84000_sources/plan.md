# Plan — CBETA and 84000 as vicaya sources

Spec: `kamma/threads/20260924_cbeta_84000_sources/spec.md`. Read it first. Every figure it quotes was measured, and the test scripts are in `artifacts/`.

## Architecture Decisions

- **Copy the GRETIL sibling pattern.** Each corpus gets one env var, one `search_*()` function in `tools/research_sources.py` that returns an empty result when the path is unset, one CLI subcommand with `--quiet` and `--limit`, and one README download section. No new module and no new dependency.
- **Search the XML on the fly with a process pool. No text cache.** The measured Taishō search takes 2.7 s at 12 workers, against 13.9 s on one core, with identical hit counts. A cache would need a build step and could go stale after `git pull`. 84000 takes 2.9 s on one core, so it needs no pool.
- **Use regex tag-stripping, not `xml.etree`.** It is the method the probes measured, and it matches how `search_sanskrit` and the SC helpers treat markup. The flatten logic in `artifacts/cbeta_probe.py::flatten` is the starting point. Split on `<body`, not `<text`, and use the per-`<char>`-block rare-character parse from the spec.
- **Put `by_text` counts before snippets.** Common terms have tens of thousands of hits (涅槃: 56,626). Per-text counts tell the agent which texts to open with `--text`/`--toh`.
- **Read the 84000 Toh number from the filename.** All 399 filenames carry it. The in-file key is missing in 3 files.
- **Extend Phase 3b; do not add a new phase.** Phase 3b is already "search another tradition's primary texts", with its gate and checklist. Renaming it avoids new gate plumbing.
- **Fix Āgama parallels in `sc_parallels` only.** `sc_search --lang lzh` is not extended, because `search-chinese` covers the same texts from CBETA.
