# Plan — Cite library books by title and author, never by number

Spec: `kamma/threads/20261119_cite_books_by_title/spec.md`. Read it first: it holds the verified root cause, the measured damage and the constraints.

## Architecture Decisions

- **The index number never leaves a run.** It stays the handle a search hit passes to `read-library`. Notes, and every check that compares a note with a run, use title and author. Stable index ids were considered and rejected (spec, "What's not included"): nothing needs them once notes carry no number.
- **Titles come from Calibre's `metadata.db`, stored at refresh time.** A new table filled at refresh keeps titles readable with the drive unmounted. Parsing folder names was measured and rejected: 22% of titles lose accents or are cut short. The table is added with `CREATE TABLE IF NOT EXISTS` beside the existing tables, because a `SCHEMA_VERSION` bump drops every table (`initialize_schema`) and would cost a full OCR rebuild.
- **One matcher, in `tools/scratch.py`.** The coverage check and the Phase 7 gate already live there and both need it. `tools/note_audit.py` drops its number branch and keeps its own author-and-title logic; it does not adopt the matcher.
- **The guard is a hard validator check, not a skill rule.** A rule in SKILL.md is what failed before: agents pasted Calibre folder numbers despite Rule F4. `validate_note.py` already runs on every note in Phase 7.
- **The migration is a one-off script in `artifacts/`,** not a project script: it runs once, on a known set of notes.
- **Footnotes become `[^lib-<n>]`,** numbered like `[^web-<n>]`. No new label scheme.

## Model Strategy

| Phase | Tier | Suggested model | Reason |
|---|---|---|---|
| 1 — Titles in the index | Fast | Sonnet | Mechanical: a new table, a lookup fix, one new field |
| 2 — Matcher and checkers | Pro | Opus | The threshold is a judgment on real data; the gate logic is subtle |
| 3 — Format and guard | Fast | Sonnet | Doc sweep and one validator rule with clear patterns |
| 4 — Migrate old notes | Pro | Opus | Rewrites 360 notes of user data; every edge case needs judgment |
| 5 — End-to-end check | Fast | Sonnet | Runs checks and reviews; the reviewers do the judging |

Before any task: prefix every helper and pytest call with `VICAYA_SCRATCH=/dev/null/none`. Run checks scoped to touched files (`kamma/tech.md`, Validation Scope): `uv run ruff check <files>`, `uv run pyright <files>`, `uv run pyrefly check --search-path . <files>`, `uv run pytest <test file> -q`.
